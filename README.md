# neuro-accountant
Нейро-бухгалтер на русском: RAG по НК РФ, ПБУ, ФСБУ и внутренним документам организации. ChromaDB + LlamaIndex + LoRA + Guardrails. Модульная конфигурация: LLM, эмбеддинги, базы знаний и правила подключаются через .env и YAML — без изменения кода. CLI, готов к FastAPI/Telegram.
##  Гибкость конфигурации

Проект спроектирован так, чтобы **всё подключаемое менялось без правки кода**:
через `.env`, YAML-файлы и структуру папок.

### Что можно менять

| Что | Где | Пример |
|---|---|---|
| **LLM** | `OPENAI_MODEL` в `.env` | `gpt-4.1-nano`, `gpt-4o-mini`, `Qwen/Qwen2.5-7B-Instruct` |
| **API-провайдер** | `OPENAI_BASE_URL` в `.env` | AITunnel, OpenAI, Ollama, vLLM, свой gateway |
| **Модель эмбеддингов** | `EMBED_MODEL` в `.env` | `multilingual-e5-large`, `ru-en-RoSBERTa`, `bge-m3` |
| **Базовая модель для LoRA** | `BASE_MODEL` в `.env` | Qwen2.5, Llama-3.1, T-lite, Saiga |
| **LoRA-адаптер** | `ADAPTER_PATH` в `.env` | Любой дообученный чекпоинт на HF или локально |
| **Пути к Chroma** | `CHROMA_PATH` в `.env` | Локально, сетевой диск, tmpfs |
| **Имена коллекций** | `COMMON_COLLECTION`, `CONTOUR_COLLECTION` | Для мультитенантности |
| **Источники данных** | `COMMON_DATA_PATH`, `CONTOUR_DATA_PATH` | Любые папки |
| **Guardrails** | `guardrails_config/config.yml` | Свои правила, regex, промпты |
| **Regex-фильтр** | `src/guardrails/fast_filter.py` | Свои чёрные списки |
| **Размер чанков** | `chunk_size`, `chunk_overlap` в `build_index.py` | Под длину документов |
| **Top-K при поиске** | `similarity_top_k` в `engines.py` | Больше — точнее, но медленнее |

### Что можно подкладывать в базы знаний

**Общая база (`data/common/`)** — обновляется без остановки сервиса:

- НК РФ, ПБУ, ФСБУ — новые редакции
- Письма Минфина и ФНС — по мере выхода
- Методички, учебники, инструкции 1С
- Внутренние FAQ и регламенты

**Контурная база (`data/contour/<org>/`)** — по одной папке на организацию:

- Учётная политика
- Договоры, счета-фактуры, акты
- ОСВ, оборотки, главная книга
- Штатное расписание, приказы
- Календарь бухгалтера, регламенты документооборота

### Как это работает

```
┌──────────────────────────────────────────────────────────┐
│  .env                →  какая LLM, какие эмбеддинги     │
│  guardrails_config/  →  какие правила защиты            │
│  data/common/        →  какие общие знания              │
│  data/contour/<org>/ →  какие документы организации     │
└──────────────────────────────────────────────────────────┘
                          │
                          ▼
              python -m src.ingest.build_index
                          │
                          ▼
              Готово — сервис отвечает по новым данным
```

### Мультитенантность

Один экземпляр обслуживает **несколько организаций**. Каждой соответствует
своя подпапка и своя коллекция в ChromaDB:

```
data/contour/
├── romashka/    →  contour_romashka
├── tulip/       →  contour_tulip
└── ip_petrov/   →  contour_ip_petrov
```

Организация выбирается по `org_id` в запросе — роутер сам подставит
нужную коллекцию. Документы клиентов **не пересекаются**.

### Обновление без перезапуска

- **Документы:** положить файлы в папку → `build_index --append` → готово.
- **Правила:** отредактировать `fast_filter.py` или `config.yml` → перезапуск
  процесса (10 секунд).
- **Модель:** поменять `OPENAI_MODEL` в `.env` → перезапуск.
- **Эмбеддинги:** поменять `EMBED_MODEL` → **полная переиндексация** (эмбеддинги
  несовместимы между моделями).
